Chapitre 1 · Comment marche le web

Internet n'est pas le Web

Internet

Les routes

Un réseau géant d'ordinateurs reliés par des câbles, des routeurs et des satellites. Né dans les années 1970–80.

Transporte : e-mails, WhatsApp, jeux, appels vidéo… et le Web.

Le Web

Les boutiques le long des routes

Des pages reliées entre elles, ouvertes dans un navigateur avec une URL. Inventé par Tim Berners-Lee en 1989.

Un service parmi d'autres qui circule sur Internet.

Demandez d'abord : « Internet et le Web, c'est pareil ? » La plupart disent oui. L'image des routes et des boutiques fait le déclic. Règle simple : si ça s'ouvre dans un navigateur avec une URL, c'est le Web.

Internet et le Web

Le test rapide : si ça s'ouvre dans un navigateur avec une URL, c'est le Web. Si ça marche dans une appli sans pages web (WhatsApp, une console de jeu), ça utilise Internet, mais pas le Web.

Image à retenir : Internet = les routes, le Web = les boutiques le long des routes. L'e-mail, WhatsApp, les jeux en ligne et Zoom circulent aussi sur Internet sans être le Web. Faites tester le « test rapide » avec 2 ou 3 exemples de la salle.

Chaque appareil connecté a deux adresses

Adresse IP et adresse MAC

Adresse IP · l'identité numérique

192.168.1.1

Adresse logique : elle dépend du réseau où tu es connecté. Ton téléphone change d'IP entre la maison et l'école.

Comme ton adresse postale : elle change si tu déménages.

Adresse MAC · l'identité matérielle

00:1A:2B:3C:4D:5E

Adresse physique : gravée dans la carte réseau de l'appareil. Elle ne change pas.

Comme ton numéro de carte d'identité : il te suit partout.

Le protocole ARP fait le lien entre les deux : il trouve l'adresse MAC qui correspond à une IP, pour que les appareils se trouvent sur le réseau local. Cliquez la carte ARP pour révéler la réponse. Slide suivante : chacun trouve sa propre IP et sa MAC.

Deux façons de travailler, en front comme en back

        
Langage pur ou framework ?

        

          

            
Langage pur · « vanilla »

            
Tu écris tout toi-même en HTML, CSS et JavaScript, sans outil en plus. Comme cuisiner à partir des ingrédients.

            
let n = 0;
btn.addEventListener("click", () => {
  n++;
  affichage.textContent = n;
});

            
  • Tu comprends ce qui se passe
  • Léger, rien à installer

            
  • Beaucoup de code répété sur un gros projet

          

          

            
Framework

            
Un cadre prêt à l'emploi avec ses règles, ses outils et des composants réutilisables. Comme un kit de cuisine guidé.

            
// React
const [n, setN] = useState(0);
return <button onClick={() => setN(n + 1)}>
  {n}
</button>;

            
  • Plus rapide sur un gros projet, structure commune
  • Grande communauté, beaucoup d'outils

            
  • Il faut apprendre ses règles en plus du langage

          

        

        

          Front React · Angular · VueCSS Bootstrap · TailwindBack Express (Node.js) · Spring Boot (Java) · Django (Python) · Laravel (PHP)
        

        
Notre choix aujourd'hui : le langage pur. Un framework n'est que du HTML, du CSS et du JS bien organisés : sans les bases, impossible de bien l'utiliser.

        
Les deux codes font la même chose : un compteur qui augmente au clic. En vanilla, on met à jour la page soi-même ; avec React, on change la donnée (n) et l'affichage suit tout seul. Nuance pour les curieux : React est techniquement une bibliothèque (on l'appelle, elle ne nous impose pas toute la structure), alors qu'Angular est un vrai framework. Les frameworks CSS (Bootstrap, Tailwind) sont revus au chapitre CSS.

Règle : const par défaut, let si la valeur change, jamais var.

Classes et héritage

        

          
class Animal {
  constructor(nom) { this.nom = nom; }
  parler() { console.log(this.nom + " fait du bruit."); }
}

class Chien extends Animal {
  constructor(nom, race) {
    super(nom);
    this.race = race;
  }
  parler() { console.log(`${this.nom} aboie !`); }
}

new Chien("Rex", "Berger").parler();  // "Rex aboie !"

          

            

              constructorappelé par new à la création

class Personne {
  constructor(nom, age) { this._nom = nom; this._age = age; }

  get nom() { return this._nom; }

  }
}
